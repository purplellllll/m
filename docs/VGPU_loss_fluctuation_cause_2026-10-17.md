# Loss 反复跳动的实证诊断

本次在原训练任务继续运行时进行只读 CPU 诊断，未修改模型、优化器、数据、运行中的损失或学习率。原始结果：`loss_cause_audit_2026-10-17.json`；配图：`loss_fluctuation_cause_2026-10-17.png` / `.svg`。服务器原始文件在项目目录下 `diagnostics/loss_cause_audit.json`。

## 已定位的主要原因：随机切换两种损失尺度，再混合记录

训练每个 microbatch 随机选输入模式：25% clean，75% 对可变 sense codon 施加 15% 随机 MASK。损失公式为：

```text
clean batch:  CE_full(clean input)                    + β KL
masked batch: CE_full(masked input) + CE_masked_sites + β KL
```

clean batch 没有选中遮挡位置，因此附加 masked CE 为零。masked batch 的 masked CE 是按选中位置的均值，**没有再乘 0.15**。这符合原设计的 Full + Masked 双项权重，并非交叉熵重复计算的实现错误；但两个模式的总 loss 尺度本来就不同。

当前日志的 `loss` 是最近一段窗口的 microbatch 平均，不是固定样本 loss，也不是整轮累计均值。通常每 10 optimizer steps 输出一次，约 80 microbatches，窗口里 clean/masked 的比例会随机变。`epoch_mean_loss` 才是当轮累计平均，进入下一轮会重新计数。

## 证据一：准确重放随机选择，解释了 92.7%～95.0% 的低/中学习率后段波动

用冻结训练数据、同一 seed 和同一长度分桶/打乱逻辑，重放 Python RNG。首轮结束时 RNG 状态与真实 checkpoint **完全相等**。由此重建每个真实日志窗口的 clean/masked 数量，按训练 step≥500 的记录拟合：

```text
logged_window_loss ≈ intercept + slope × masked_batch_fraction
```

| LR | 窗口数 | Pearson r | R² | 原始 loss 标准差 | 回归残差标准差 |
|---|---:|---:|---:|---:|---:|
| 0.01 | 513 | 0.9748 | 0.9502 | 0.05962 | 0.01330 |
| 0.001 | 91 | 0.9706 | 0.9420 | 0.06056 | 0.01459 |
| 0.0001 | 63 | 0.9628 | 0.9271 | 0.05384 | 0.01454 |
| 0.1 | 513 | 0.0506 | 0.0026 | 1.75965 | 1.75740 |

在 0.0001 的这段真实日志里，masked-mode microbatch 占比从 66.25% 到 86.25% 不等，拟合斜率为 1.1500。仅这个差异即可对应约 0.23 的总 loss 差。这里的 R² 是本次记录的单变量拟合结果，不是对所有未来波动的普遍承诺；KL 调度、模型逐步学习等仍可贡献残差或与模式比例偶然相关。

0.1 的波动不符合这个解释：其后段窗口标准差高达 1.76，且 KL 和验证 CE 大幅变化，因此该组另有实际优化不稳定；不能把四组一概称为正常采样波动。

## 证据二：冻结权重后，切换输入模式即可复现大幅 loss 差

使用已保存的 **LR=0.001、epoch 1、step 1116** checkpoint，在 CPU 上选 4 条真实训练 CDS（96～128 codons），每种条件重复 12 次。没有执行 optimizer.step。

| 条件 | 平均 loss | 重复计算标准差 |
|---|---:|---:|
| 固定 clean 输入、eval、z=μ | 0.024516 | 0 |
| 固定 masked 输入/位置、eval、z=μ | 1.206043 | 0 |
| 固定 masked 输入，改为采样 z | 1.241676 | 0.016603 |
| 固定 masked 输入，启用 dropout、z=μ | 1.222457 | 0.046646 |
| eval、z=μ，但每次重新选 mask | 1.156212 | 0.096696 |

固定所有条件时重复 loss 完全一致，说明没有不明的计算漂移。clean 与 masked 模式的确定性总损失差为 **1.181527**，可精确分解为：

```text
附加 masked CE                  +1.031330
完整位置 CE 因输入遮挡变难        +0.151399
β × KL 的差                     -0.001201
合计                            +1.181527
```

该探针只覆盖一个 checkpoint 和一个短序列 batch，不能用其 dropout/z 方差量级推断所有 batch；随机模式比例对真实日志的影响则另有上面的全日志重放证据。

## 其他因素与代码核查

- Dropout、VAE 重参数采样、每次重选 mask 都会在权重不变时引入噪声，已由冻结实验确认。
- 样本长度、氨基酸组成和同义密码子分布不同。CE 按各 microbatch 的有效位置求均值，再对 microbatch 等权，日志不是全窗口按 token 加权。
- 第一轮 β 从近零升至 0.001，loss 所对应的正则权重在变化，不是固定目标的优化轨迹。
- 梯度累积每组使用 `loss/group_size`，每组只更新一次；最后不足组按真实大小归一化。没有发现重复 step、缺失 backward 或累积时遗漏清梯度。最新学习率实验的完整组大小为 8。
- 原始 `steps.jsonl` 没有逐窗口记录 clean/masked 数量和各 CE/KL 分量，只有总 loss。这是监控信息不足，之前仅凭它描述“loss 不下降/平台”不够完整。epoch 指标已包含分量，但频率低。
- hard synonymous mask 使网络只能在目标 AA 的合法 codon 集合内选择。真实遮挡密码子包含不能由现有上下文唯一确定的差异，不应期待 masked CE 归零，更不应要求随机训练日志逐行单调下降。

## 应如何监控，而不是单纯平滑曲线

保留真实训练总 loss，同时分开记录 clean/masked 模式下的 CE_full、CE_mask、KL、β 和样本数；在每组 checkpoint 用固定样本、固定遮挡、eval、z=μ、固定 β 做可比探针。日志中可另列固定模式比例下的诊断均值，但必须明确它不是原始实际训练 loss。

本次图中的 composition-adjusted 曲线只减去了回归估计的模式配比偏差（校正到 75%），不修改任何训练值，也不是新的验证成绩。当前仍继续原 0.0001 实验，未为追求平滑而中断或改写训练目标。

若另做降低训练噪声的实验，可以在每个 8-microbatch 累积组固定 2 clean + 6 masked，而不是独立随机抽模式；这改变采样方案，应单独建实验比较，不能悄悄混入当前 5 轮对照。
