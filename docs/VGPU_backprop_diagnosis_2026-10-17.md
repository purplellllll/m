# 0.01 组反向传播与 loss 平台检查

检查针对运行中的真实训练任务，读取首轮 checkpoint（epoch 1、step 1116）和截至 step 1490 的日志。后续组尚未在本报告中评估。本次未修改、停止或重启三组对照实验。

## 参数确实发生更新

- AdamW 为全部 158 个参数张量建立了状态，所有更新计数均为 1116，所有一阶/二阶矩均非零。
- 用同一配置和 seed 重建 CPU 初始化状态后逐张量比较：158/158 参数张量均发生变化。
- Encoder 权重相对初始状态的整体 L2 差异比为 3.723；Decoder 为 2.719。该比值是整个模块的聚合变化量，不是单次更新大小。
- 训练记录的裁剪前梯度范数非零，首个记录为 3.6375；截至第一轮后的早期检查，最小值约 0.04277，最大值约 401.85。梯度裁剪阈值是 1.0。
- 在独立 CPU 进程载入同一 checkpoint，用合成短序列反向诊断，总损失对 Encoder/μ/logvar/Decoder/output 的梯度均非零且有限。关闭 KL 后，重建损失对 Encoder 的梯度范数仍为 0.01705，对 μ 头为 0.003444。因此不只是 KL 正则在推动 Encoder，重建梯度链路也连通。
- CPU 诊断不执行 optimizer.step，不修改 checkpoint，不使用训练 GPU，也不改变运行中任务的随机状态。

## 学习效果已出现平台，不能仅归因为日志波动

按每 25 条日志记录取窗口均值（非 token 加权）：

| 更新步范围 | 平均训练 loss |
|---|---:|
| 1–240 | 2.19868 |
| 250–490 | 1.98646 |
| 500–740 | 1.98419 |
| 750–990 | 1.98096 |
| 1000–1230 | 1.97933 |
| 1240–1480 | 1.96646 |

结论是初期下降后进入平台，而非完全没有下降。窗口长度、所含 microbatch 长度和 clean/masked 配比不同，不能把表中变化当成同一批样本上的严格优化轨迹。

第一轮验证指标：

| 指标 | CE / 数值 |
|---|---:|
| clean 可变位 CE | 1.145131 |
| zero-z 可变位 CE | 1.145222 |
| 同 AA 内 shuffle-z 可变位 CE | 1.145154 |
| masked 位 CE | 1.145745 |
| 条件频率基线 masked CE | 1.144230 |
| clean 可变位准确率 | 42.9958% |
| masked 可变位准确率 | 42.9450% |
| 条件频率基线 masked 准确率 | 43.0675% |
| active latent dimensions（μ 方差 >0.01） | 0 |
| clean KL / token | 6.23460 |

clean、zero-z、shuffle-z 使用同一批全体可变位置；masked 与频率基线使用同一批选中遮挡位置。两组支持集不同，不能直接将其 CE 差都视为同一个对照。

首轮 masked CE 比频率基线还差约 0.132%。固定 AA 后，置零/打乱 z 的 CE 差分别仅约 0.000091 / 0.000023。结合 0 个活跃 latent 维度，说明该 checkpoint 对 z 的依赖很弱，出现潜变量未被有效利用/塌缩迹象；并非声称 KL 已严格为零或完整后验等于先验。

## 对 loss 波动的解释与下一步

训练日志的 `loss` 是短窗口均值，不是同一固定 batch 的 loss：样本/长度/AA 组成、clean 与 15% masked 输入、dropout、z 采样均变化；第一轮 β 也从接近零升至 0.001。clean batch 的 masked 附加项为零，因此两类 batch 的总 loss 尺度不同，单条日志不要求单调下降。但这些原因不能解释验证 CE 停在频率基线附近，学习质量问题确实存在。

0.01 对当前配置可能过大；早期大梯度与平台提供线索，尚不能只凭首轮确定因果。KL 压力和 AA 条件捷径也可能使模型弱化 z，需要受控实验区分。当前按用户指定继续完成 0.01 / 0.1 / 0.001 三组各 5 轮，再按固定验证 CE 和 z 消融判断。若 0.001 仍出现同类问题，可另建 1e-4～3e-4、较慢 KL warm-up/较小 β 的单因素对照，不混入本轮既定实验。
